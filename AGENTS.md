- Production builds read public backend values from vite.config define fallbacks — .env is gitignored and missing in deploys.
- OTC escrow uses one bot-held OurBank-style wallet per deal (handle `escrow-<postId>`), gas sponsored by the bot, settled/refunded by the X poller — no Move package needed (deploys are forbidden).
- Cross-chain auto-swap: orders live in cross_chain_orders; the X poll loop swaps only SUI above the order's baseline balance, claiming pending→swapping atomically so a deposit is never swapped twice.
- Each OurBank wallet gets one lazily-created EVM deposit address (bank-evm.server.ts), Turnkey-first with encrypted local fallback; never replaced once set — funds could be stranded.
- OurBank EVM deposits are swept to the Sui wallet by evm-sweep.server.ts (Mayan; Robinhood hops to Arbitrum via Relay) and auto-bought via cross_chain_orders; gated by EVM_SWEEP_ALLOW and one in-flight sweep per address/chain/token so a deposit is never sent twice.
- Each OurBank wallet gets one lazily-created Solana deposit address (bank-sol.server.ts), Turnkey-first with encrypted local fallback; never replaced once set — funds could be stranded. No Solana sweeper yet, so the UI says "don't send funds".
- OurBank Solana deposits (SOL, USDC) are swept by sol-sweep.server.ts via NEAR Intents 1Click (no Solana SDK — hand-built legacy txs) into SUI on the Sui wallet, then auto-bought via cross_chain_orders; same gate as EVM sweeps, one in-flight sweep per address.
- Background EVM/SOL deposit sweeps are off unless AUTO_SWEEP_BACKGROUND=1; deposits only bridge on an explicit user command — users must control when funds move.
- Funded launches (pay with SOL/ETH/BNB) live in fundedLaunch*.ts: review+confirm, bridge with no auto-buy order, launch via executeLaunchRequest once SUI arrives; refused while an auto-buy order is open so arriving SUI is never swapped.
- BNB bridges fall back to BNB→SOL (Relay, into the user's own OurBank Solana address) when 1Click refuses; maintainBnbSolHops then bridges that SOL to Sui once per sweep row (status sent→hopping→hopped, hop note kept in evm_sweeps.approve_tx) so funds are never sent twice.
- Terminal-attached token pictures are uploaded to the private `token-icons` bucket and served via /api/public/icon/<userId>/<uuid>.<ext> — public buckets are blocked and data URLs are too long for on-chain icon URLs.
- Perpsplexity funded launches swap bridged SUI above launch cost + 2 SUI gas reserve into USDC and set it as the creator's first buy — the curve trades in USDC; a failed swap never blocks the launch.
- SUI → ETH/BNB hops through the user's own OurBank Solana address (sui_out_hops: leg 1 SUI→SOL via 1Click, leg 2 by maintainSuiOutHops via 1Click for Base/Arbitrum ETH / Relay for BNB and Robinhood Chain ETH, claimed sent→hopping so leg 2 is sent once) — direct SUI→EVM corridors are refused or have a $1,000 floor.
- Telegram Mini App (/tg) authenticates by verifying Telegram initData HMAC server-side on every call (src/lib/tg); tg_* tables are service-role only — no Supabase session exists inside Telegram.
- Telegram webhooks persist atomic update/confirmation claims before acknowledging; Nitro Request.waitUntil runs queued work, with the authenticated poller draining pending jobs as fallback; processing jobs never auto-replay because submission outcomes can be ambiguous.

- Telegram swaps preserve full, case-sensitive coin types; bot cards carry contracts in bot-authored message text across confirmation because callback payloads are limited to 64 bytes.
- SOL → SUI bridges try NEAR Intents first, then Mayan MCTP (mayan-sol.ts, hand-built v0 tx, simulated before sending) — two providers so one solver outage doesn't block bridging, and no Solana SDK in the worker.
- Solana balances and bridge RPC calls share sol-rpc.server.ts with public-first endpoints and temporary outage cooldowns; broadcast fallback reuses the identical signed payload to avoid creating duplicate transfers.
- OurBank Sui balance reads use paginated official GraphQL through sui-balances.server.ts; Telegram uses the same response's metadata and reports read failures rather than empty holdings, avoiding retired RPC mirrors.
- Swap input resolution and preflight simulations use the official Sui GraphQL SDK client in bank-swap.server.ts, including connected-wallet preparation and launch-curve estimates, because legacy Suiscan JSON-RPC is retired.
- Sui reads/submits go through `rpc()` → sui-rpc-compat.server.ts, which answers legacy JSON-RPC methods via the official GraphQL service in JSON-RPC shapes — all public JSON-RPC mirrors were retired (Oct 2026); never add a JSON-RPC mirror URL back.
- Numbered NFT sends use the shared NFT parser and exact collection/edition matching; missing or ambiguous editions select nothing to avoid transferring the wrong collectible.
- Web terminal NFT commands route through the shared OurBank handler and require sign-in, so they never fall through to conversational interpretation.
- Kiosk NFT sends (kiosk.ts) only satisfy royalty_rule + kiosk_lock_rule, calling the rules package version the collection links against; locked items go into a new recipient-owned kiosk, and any other policy rule is refused so a send never guesses.
- Mini App NFT inventory derives the main wallet from verified Telegram/X identity, sends exact object IDs through the shared command handler, and hides collection types only in account-scoped device storage so hiding never transfers assets.
- drip.market data is read via its public search API in src/lib/drip.functions.ts (cached 5 min); marketplace actions are outbound links only — OURBLAST never signs drip trades.
- Telegram users without a linked X account get a native OurBank wallet keyed `tg-<telegramId>` (tgIdentity.server.ts); linking X keeps it as an extra wallet slot — X handles can't contain "-", so no collisions and funds are never stranded.
- Blast advisory is read-only with bundled official references and separate planning math; live snipes use exact-wallet unsigned simulations and min-output protection, never modern v2 formulas for historical MemezFun deployments, to avoid unsupported launch assumptions.
